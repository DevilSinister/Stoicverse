# Stoicverse (ask-stoic) — Full Project Audit

**Date:** 2026-09-06 · **Branch:** `codex-Redesign` @ `c8da533` · **Stack:** Next.js 16.2.10 (Turbopack, App Router) · React 19.2.4 · Supabase (Postgres 17.6) · Tailwind 4 · TypeScript 5 strict

**Scope:** 127 TS/TSX source files (~11.9k component lines), 26 SQL migrations, 11 API routes, 7 server-action modules, 1 Supabase Edge Function, 9 test files, live database advisories, dependency audit, docs and repo hygiene.

---

## Verdict

The **security architecture is genuinely good** — a rare thing. RLS is enabled on all 34 tables, every privileged server action re-authorises rather than trusting the proxy, `safeNextPath` correctly defends open redirects against backslash and control-character smuggling, the hand-rolled Stripe signature check uses `timingSafeEqual` with a replay window, signup responses are user-enumeration-safe, and the account-settings surface is uniformly rate-limited.

What undermines it is **consistency and verification**. Three API routes were written to a visibly lower standard than the other eight, and one of them writes to the database with the service-role key using a number the browser supplied. The migration directory has drifted so far from the live database that it can no longer be replayed. And the CI checklist the team wrote for itself has never been wired to a CI system — while the security test suite it names exits green having run nothing.

| Area | Verdict |

## Critical

### C1 — A failed Stripe webhook is never retried, so a paid member never gets access

`src/app/api/stripe/webhook/route.ts:38-42`

The handler records the event **before** processing it, then treats a duplicate-key error on re-delivery as "already handled":

```ts
const { error: receivedError } = await admin.from("stripe_webhook_events")
  .insert({ stripe_event_id: event.id, event_type: event.type, payload: event, processed: false });
if (receivedError?.code === "23505") return NextResponse.json({ received: true });
```

If processing then throws (line 79), the route returns 500 and Stripe retries. The retry hits the unique constraint and returns **200 immediately, without processing**. The row keeps `processed: false` forever.

**Impact:** a customer is charged, `checkout.session.completed` fires, a transient Supabase error occurs, and the membership is never activated. No retry, no alert — only a `processed = false` row nobody queries. This is silent revenue loss on the platform's only paid path.

**Fix:** on `23505`, re-read the row; if `processed` is false, fall through and process it. Return 500 on any unprocessed failure so Stripe keeps retrying, and add a reconciliation query over `stripe_webhook_events where processed = false`.

### C2 — Any member can rewrite every other member's course progress

`src/app/api/courses/videos/[id]/video/route.ts:16-45`

`POST` takes `durationSeconds` **from the request body**, prefers it over the server-side Drive lookup, and then uses the **service-role admin client** to rewrite the video's duration and recompute `completion_percentage`, `is_completed`, and `completed_at` for **every user who has watched it**:

```ts
const browserDuration = typeof payload.durationSeconds === "number" && ... ? payload.durationSeconds : null;
const durationSeconds = browserDuration ?? await getGoogleDriveDurationSeconds(fileId);
...
const admin = createAdminClient();
await admin.from("course_videos").update({ duration_seconds: durationSeconds }).eq("id", id);
const { data: history } = await admin.from("course_video_progress").select("user_id, watched_seconds").eq("video_id", id);
// recomputes and writes is_completed for every row
```

The only gate is `get_course_video_file_id`, which any member with access to the video passes.

**Attack:** POST `{"durationSeconds": 1}` — everyone's `completion_percentage` becomes 100 and `is_completed` becomes true, so course-completion grants and tier progression fire for the entire cohort. POST `86400` wipes everyone's completion instead. The route has **no origin check**, so this is reachable cross-site with a victim's cookies.

**Fix:** never accept duration from the client, or accept it only as a *creator-authenticated* write. Gate the admin-client branch behind `requireInfluencer()`, add `rejectUntrustedOrigin`, and validate `id` as a UUID.

## High

### H1 — The service-role client silently falls back to a fake key

`src/lib/supabase/admin.ts:8`

```ts
const serviceRoleKey = process.env.SUPABASE_SERVICE_ROLE_KEY || "dummy-service-role-key-for-build";
```

A production deploy missing this variable does not fail — it constructs an admin client that will fail *at runtime, inside the webhook handler*, producing C1's silent-loss path instead of a startup error. Throw when the variable is absent outside `next build`.

### H2 — `npm run test:security` exits 0 having run nothing

`tests/security/rls.integration.mjs:13-14`

All 7 RLS tests self-skip when the `RLS_*` fixture variables are unset. Measured on this machine: `pass 0, fail 0, skipped 7`, exit code 0. `SECURITY_DEPLOYMENT.md` instructs CI to run this command as a gate. It is a green light that verifies nothing. Fail hard when the fixtures are missing in CI (`if (missing.length && process.env.CI) throw`).

### H3 — 10 high-severity dependency advisories

`npm audit --omit=dev` reports 13 (3 moderate, 10 high):

- **undici 7.0.0–7.28.0** — 5 advisories: response desynchronization via the retry interceptor, cross-user cache disclosure, CRLF injection via blob body `type`, cookie attribute injection. Fixed by `npm audit fix`.
- **sharp <0.35.0** — 4 libvips CVEs (CVE-2026-33327/33328/35590/35591), transitively via `next`. Requires `next@16.3.4`.

### H4 — The migration directory can no longer reproduce the database

Comparing `supabase/migrations/` against the live migration table:

**Applied but absent from the repo (5):** `revoke_public_execute_on_secdef_functions`, `member_dashboard_turnover`, `creator_member_operations`, `fix_gift_subscription_rls`, `keep_gift_rpc_security_invoker`.

**In the repo but never applied under that name (4):** `creator_overview_metrics`, `creator_overview_trends`, `membership_expiry_and_staff_event_override`, `discord_style_community_channels`.

**Every version timestamp differs** (repo `20260711000000` vs applied `20260711030323`), and `20260712000000_security_access_boundaries` was applied as `security_access_boundaries_and_sinister_influencer_v2` — a different, later revision.

The live database has tables (`member_dashboard_turnover`, `member_weekly_turnover`, `member_moderation_events`) and a function (`set_member_platform_role`) with no repo definition. `supabase db push` against a fresh project would produce a **different schema** than production, and would attempt to re-apply everything against production. Disaster recovery and the RLS test suite both depend on this directory being authoritative. Reconcile with `supabase db pull` / `db diff` before the next release.

### H5 — No CI exists

`.github/workflows/` is absent. `SECURITY_DEPLOYMENT.md` prescribes `npm audit --omit=dev`, `npm run lint`, `npm run test:security`, and `npm run build` as CI gates. Today all four are manual — and as measured below, three of them currently fail or no-op.

## Medium

### M1 — Three API routes were written to a lower standard than the other eight

The proxy matcher excludes `/api`, so each route is its own boundary. Eight routes do origin check + auth + rate limit + UUID validation. These do not:

| Route | Origin (CSRF) | Auth check | Rate limit | UUID check |
|---|---|---|---|---|
| `courses/videos/[id]/progress` | no | no | no | no |
| `courses/videos/[id]/stream` | no | no | no | no |
| `courses/videos/[id]/video` | no | no | no | no |

They lean entirely on RLS via RPC. That holds for read authorisation, but leaves them CSRF-reachable and unmetered — and `/stream` proxies unbounded Google Drive bandwidth through the origin with no per-user cap. Compare `courses/lessons/[id]/progress`, which does all four correctly; these three should match it.

### M2 — Raw Postgres error messages are returned to clients

~20 sites across `courses/actions.ts`, `community/actions.ts`, `creator/members/actions.ts`, and `videos/[id]/progress/route.ts` return `error.message` verbatim, e.g. `return { error: error.message }`. This leaks column names, constraint names, and policy names. The auth and settings modules already do this correctly (fixed strings) — apply the same treatment.

### M3 — Video reordering is non-transactional and corrupts `sort_order` on partial failure

`src/app/courses/actions.ts:104-136` and `:181-207`

Both `updateCourseVideo` and `reorderCourseVideos` work around the unique `(course_id, sort_order)` constraint with a two-pass shuffle: move every row to `sort_order = length + 10000 + i`, then assign final positions. Each pass is N sequential round-trips with an early `return` on error.

If the second pass fails midway — network blip, timeout, RLS rejection — videos are **left at offsets above 10000** and the course renders in a broken order with no recovery path. Move this into a single `SECURITY DEFINER` RPC with a deferred constraint, or wrap it in a transaction.

### M4 — Any staff member can silently rewrite any other staff member's post

Live policy `posts_staff_update` is `USING (is_staff() AND can_view_channel(channel_id))` — **no `author_id` predicate** — and `editStaffPost` (`src/app/community/actions.ts:51-68`) adds no author check either. Any moderator can rewrite the influencer's announcements, with only `updated_at` as evidence and no moderation-event record. If this is intended moderation power, log it to `member_moderation_events`; if not, add `author_id = auth.uid()` to the policy.

### M5 — Unauthenticated outbound fetch before the auth check

`src/app/courses/actions.ts:100-104` calls `getGoogleDriveDurationSeconds(fileId)` — up to three outbound HTTP requests — **before** `requireInfluencer()` on line 105. Reorder so authorisation precedes network I/O.

### M6 — In-memory rate limiter

`src/lib/security/request.ts:3` holds windows in a module-level `Map`: per-process, and reset on every deploy. This is honestly documented in code and in `SECURITY_DEPLOYMENT.md`, but it is the only limiter protecting login, signup, and checkout. It must move to Redis or Postgres before a second instance exists.

### M7 — ESLint reports 3 errors and 11 warnings, and nothing enforces them

- `EventsView.tsx:75` — **error**: `setState` called synchronously in an effect body, causing cascading renders on a 515-line component.
- `EventsView.tsx:476,503` — **errors**: unescaped entities.
- 11 warnings: unused `LegacyCourseVideoPlayer`, unused `LegacyDashboardView`, 5 unused symbols in `CreatorEventsView`, 2 unoptimised `<img>` in `CommunitySurface`, 1 stale `eslint-disable` in `safe-path.ts`.

`"lint": "eslint"` has no `--max-warnings`, and Next 16 does not lint during `next build`, so none of this blocks anything.

### M8 — Database advisories from the live project (`rlzqjbmupvoveflbyqzn`)

- `event_rooms` and `lesson_assets` have **RLS enabled with zero policies** — deny-all by default, which is almost certainly intended (both hold secrets reached only via `SECURITY DEFINER` RPCs), but it should be an explicit documented deny rather than an implicit one.
- **Leaked-password protection is disabled** in Supabase Auth. One dashboard toggle; enables HaveIBeenPwned checks.
- `pg_trgm` is installed in the `public` schema.
- 21 `SECURITY DEFINER` functions are executable by `authenticated`. Most are intentional gate functions, but `set_member_platform_role` and `save_creator_event` warrant an explicit `REVOKE` / re-check pass.
- 18 unindexed foreign keys — `posts.author_id`, `reactions.user_id`, `mentorships.user_id`, and `lesson_progress.lesson_id` are the ones on hot paths.
- 18 never-used indexes, including all 6 trigram indexes added in `search_trigram_indexes` — meaning the dashboard search is **not** using them.
- 20 tables carry multiple permissive policies for the same role+action, each evaluated on every query.

## Low / Hygiene

- **L1 — `npm run build` currently fails locally.** `tsconfig.json` includes `.next/dev/types/**/*.ts`, and a stale dev-server artifact still references three deleted routes (`creator/members/turnover`, `api/creator/members/[id]`, `api/creator/members`). Source itself typechecks **clean** — verified against a tsconfig scoped to `src/` + `proxy.ts`. A fresh clone is unaffected; `rm -rf .next` clears it. Consider dropping `.next/dev/types` from `include`.
- **L2 — The test suite measures text, not behaviour.** All 8 contract files (25 tests, all passing) are regex assertions over source strings, e.g. `assert.match(page, /redirect\("\/creator\/members"\)/)`. They catch accidental deletions; they cannot catch a logic error. Against ~11.9k lines of components, runtime coverage is effectively zero. The three highest-value targets are the Stripe webhook, `safeNextPath`, and the proxy's role-routing matrix.
- **L3 — README is unmodified `create-next-app` boilerplate** for a 127-file production application. `SECURITY_DEPLOYMENT.md` is genuinely good and should be linked from it.
- **L4 — No `.env.example`.** `.env.local` defines 3 of ~12 required variables (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_APP_URL`). Missing locally: `SUPABASE_SERVICE_ROLE_KEY`, all 4 Stripe variables, both Resend variables, `GOOGLE_DRIVE_API_KEY`, `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY`. Checkout, webhooks, email, and Drive duration lookup are all dead in local dev with no error explaining why.
- **L5 — Two competing lockfiles** are committed: `package-lock.json` (354 KB) and `pnpm-lock.yaml` (214 KB). Installs are nondeterministic depending on which tool runs. `pnpm-workspace.yaml` exists, so pnpm appears intended — delete the npm lockfile.
- **L6 — Duplicated pages.** `src/app/creator/master/page.tsx` is a near-verbatim copy of `renderMasterPage` in `src/app/master/page.tsx` (same five queries, same shape) but does not call it — the shared helper exists and is bypassed. Alias-only routes `/log-in` and `/sign-up` redirect to `/login` and `/signup`.
- **L7 — Dead code.** `LegacyDashboardView`, `LegacyCourseVideoPlayer`, a ~30-line commented-out legacy block at the top of `src/app/courses/page.tsx`, and `addLesson` in `courses/actions.ts` which exists only to return an error string.
- **L8 — Inconsistent UUID validation.** `courses/actions.ts:10` and `community/actions.ts:8` use `/^[0-9a-f]{8}-[0-9a-f-]{27}$/i`, which accepts hyphens in any position; `creator/members/actions.ts` and every API route use the strict form. Extract one shared validator.
- **L9 — `updateCourseVideo` is written in minified style** (`const videoId=value(formData,"videoId"), title=...`) inside an otherwise conventionally formatted file. There is no Prettier config in the repo.
- **L10 — Three files exceed 1,000 lines:** `CommunitySurface.tsx` (1,500), `CreatorEventsView.tsx` (1,064), `CreatorCourseManagerV2.tsx` (1,011).
- **L11 — Large non-source files are tracked:** a 2.9 MB git bundle (`codex-influencer-features-21475a1.bundle`), a 724 KB `preview-desktop.png`, a 191 KB `claude-fable-5.md`, and a nested `.repo-git/` directory — all at the repository root.
- **L12 — CSP `img-src` allows all of `https:`**, which is broad for an app whose only external image source is Supabase storage.
- **L13 — The proxy issues 3 database queries on every protected navigation** (`memberships`, `profiles`, `account_deletion_requests`), parallelised but uncached. A short-TTL cached claim or a single RPC would cut per-navigation latency meaningfully.
